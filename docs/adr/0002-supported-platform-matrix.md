# ADR-0002: Supported platform matrix

Status: Accepted  
Date: 2026-10-22  
Work item: MVP-00

## Context

MVP-00 must fix the supported Go, PostgreSQL, Node.js, and browser versions.
These choices affect available SQL features in migrations, the language
features used by the backend, the frontend build, and the E2E matrix.

## Decision

### Go

- The `go` directive in `go.mod` is `1.26`. The exact patch release is pinned
  by both the `toolchain` directive and `.go-version`, so local builds, CI, and
  container builds stay aligned. It changes only through reviewed dependency
  updates.
- Developers with an older local Go use `GOTOOLCHAIN=auto` to obtain the pinned
  toolchain; the build never depends on the developer's installed version.
- The project follows the upstream Go support policy: it builds with the pinned
  toolchain and moves to a new Go major within one minor release of it becoming
  the oldest supported upstream major.
- Release binaries and images are built with `CGO_ENABLED=0`.

### PostgreSQL

- Supported server majors for the MVP: **17 and 18**. The minimum is 17.
- Migrations may use any feature available in PostgreSQL 17 and must not use a
  feature introduced later.
- Integration tests run against both supported majors. The production Compose
  file defaults to 18.
- Adding a newer major is a matrix update plus green integration tests; dropping
  one requires an ADR and release notes.
- Required extensions: none in the MVP. `pg_trgm` may be proposed in MVP-07 by
  ADR if built-in text search proves insufficient. The runtime role never
  creates extensions (see `docs/SECURITY_ARCHITECTURE.md` section 8).

### Node.js (build-time only)

- Node.js **24 LTS** is the only supported version for building, linting, and
  testing the frontend. The exact version is pinned in `.nvmrc` and
  `package.json` `engines` in MVP-01.
- Node.js is never present in the production image.
- The package manager is npm with a committed `package-lock.json`; installs in
  CI use `npm ci`.

### Browsers

- Supported: the two latest stable major versions of Chrome, Edge, Firefox,
  and Safari (macOS and iOS), plus the current Firefox ESR.
- The frontend build targets the oldest of these; no polyfills for
  unsupported browsers.
- Playwright E2E runs on Chromium in every pipeline. Firefox and WebKit runs
  are required before an MVP release (MVP-15).

## Consequences

- Migrations can rely on PostgreSQL 17 features. Identifiers are generated by
  the application (ADR-0009), so no UUID extension is needed.
- The integration matrix doubles database test time; this is accepted.

## Alternatives considered

- Supporting PostgreSQL 15 and 16: rejected; more matrix cost with no current
  user base to justify it.
- pnpm or Yarn: rejected for the MVP; npm ships with Node.js and keeps the
  toolchain small.
